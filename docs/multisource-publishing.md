# 多源输入与多形态发布

简迹 CV 把产品主链路定义为：

```text
来源资料 → 候选稿 → 用户决定是否合并 → 编辑器逐项复核 → 规范 ResumeContent → 多形态渲染 → 私有下载或手动公开发布
```

所有格式都消费同一份规范正文。解析器和模型只能提出候选内容，不能绕过修订检查直接写简历。编辑器下载网页或 ZIP 前要求确认联系方式与公开风险；服务端只生成下载文件，不执行公开发布。

## 当前能力矩阵

| 方向 | 格式 | 当前处理方式 | 原件是否上传 |
| --- | --- | --- | --- |
| 输入 | TXT / Markdown | 浏览器本地按纯文本读取；识别预设标题、常见 Markdown 标题标记和约定分隔格式 | 否 |
| 输入 | 简迹 JSON | 严格校验 `ResumeContent`；单份数据可选择完整恢复正文，元数据不恢复 | 否 |
| 输入 | DOCX | 实际解压字节、XML 部件与结构复杂度有界预检后，在可终止 Worker 中转换；保留可识别章节、段落和列表线索，表格需复核，图片与版式不保留 | 否 |
| 输入 | JPEG / PNG / WebP | 校验实际格式与像素上限后本地预览；用户手工录入的文字只能进入简介、技能或奖项，原图不进入输出 | 否 |
| 输出 | PDF | 浏览器打印，保留可选中文本 | 不适用 |
| 输出 | DOCX | 浏览器生成真实 OOXML Word 文档 | 不适用 |
| 输出 | PNG | 独立 DOM 生成 A4 首图或长图；极长内容自适应倍率，超出可靠画布上限时拒绝并提示 PDF | 不适用 |
| 输出 | JSON / TXT | 可移植简历数据或 ATS 纯文本；JSON 回导只恢复正文，不等同于完整账号恢复 | 不适用 |
| 输出 | HTML | 静态单栏或无脚本交互式个人主页 | 不适用 |
| 发布 | GitHub Pages | 下载 ZIP，内含页面、`.nojekyll` 和发布步骤 | 不请求仓库权限 |

DOCX、图片和粘贴文字得到的内容都会先进入候选稿。多份候选对个人信息和简介采用先到先得，并显式列出差异；同签名经历或项目的地点、描述、链接不同时也会警告，列表在 schema 上限内去重追加。应用到当前简历时，只有显式勾选后个人信息和简介才覆盖已有值；单份 JSON 还可选择完整替换 `ResumeContent`。最终内容继续走 Zod、`expectedRevision` CAS 和修订快照。当前没有字段级来源选择，用户仍需在编辑器逐项复核。

Word 的转换不访问外部文件、不使用文档内嵌样式映射、不挂载生成的 HTML；文字节点仅解码一次。解压总量上限 24 MB、正文 XML 上限 4 MB、样式 XML 上限 1 MB，并限制 XML 标记总数；预检 15 秒、完整转换 10 秒超时后终止。复杂表格、非标准章节或只有图片的扫描文档无法保证自动结构化，转换警告会随候选稿展示。

## 图片边界

当前图片流程刻意不提供“看似智能”的假 OCR：读取前检查文件魔数、声明 MIME、尺寸与像素上限，之后使用本地 object URL 预览并在关闭对话框时释放。进入正文的只有用户核对并输入的文字，不保存 data URL、EXIF 或原件，图片也不会成为简历头像或导出素材。

云端视觉理解上线前必须具备以下完整链路：

```text
私有上传 → 实际 MIME / 大小 / 哈希检查 → 隔离扫描 → 图片安全重编码与 EXIF 清除
        → 异步 OCR / 视觉抽取 → 字段级来源与置信度 → 人工确认 → 修订 CAS 应用
```

未来实现云端文件能力时，D1 应只保存资产元数据、导入任务、候选字段和来源定位，R2 才保存原件与安全变体；公开网页只能读取安全变体。D1 与 R2 删除无法同事务完成，必须使用对象删除 outbox、幂等消费和保留期任务。

## 网页与 GitHub 发布

每份网页简历都是独立静态微站，不把需要 Auth、D1 和 API 的主应用改成静态导出。交互版使用章节导航、滚动锚点、响应式布局和原生折叠控件，在禁用脚本时也完整可读。

当前 GitHub Pages 路径是明确的手动发布包：浏览器只下载 ZIP，不读取仓库，也不记录发布状态。未来的一键发布必须与 GitHub 登录身份分离：

1. 取得独立的最小仓库写权限，禁止静默复用登录 OAuth。
2. 用户明确选择专用仓库、分支和目录，并锁定要发布的简历 revision。
3. 写入产品 manifest；发现未知文件或非产品目录时拒绝覆盖。
4. D1 记录仓库、分支、路径、revision、产物 hash、隐私选项、URL 和状态。
5. 重新发布和撤回都需确认；撤回不能承诺清除搜索缓存、fork 或他人副本。

需要访问统计、联系表单、私密访问或限时链接时，应作为服务端 publication 能力实现，不能塞进 GitHub Pages 静态包。

## 下一阶段数据模型

云端文件能力需要 Resume schema v2，并在版本表中同时保存 schema version。建议新增稳定实体：

- `assets` / `asset_variants`：归属、用途、状态、哈希、检测 MIME、安全变体。
- `resume_asset_links`：`source-document`、`portrait`、`certificate`、`screenshot`、`gallery`。
- `resume_import_jobs` / `resume_import_proposals`：解析状态、基础修订、解析器版本、警告、字段级来源和确认结果。
- `resume_export_jobs`：按 `resume revision + renderer version + privacy options` 生成可过期产物。
- `publications`：发布目的地、产物 hash、隐私选择、状态、URL 和撤回记录。
- `object_deletion_outbox`：保证账号删除、简历删除和保留期清理最终移除对象。

未来的证书能力需要稳定 ID 的 `credentials`，不能长期依赖 `awards` 数组下标；头像也只能保存私有 `assetId`，不能把外部 URL 或原始 data URL 写进正文。
