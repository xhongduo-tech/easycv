# 简迹 CV

简迹 CV 是一个用 AI 辅助用户完成简历的目标驱动平台。留学申请与毕业求职不是两套产品，而是新建简历时选择的两种用途：

- 留学申请：根据大学、地区与申请方向组织教育、研究和项目证据。
- 毕业求职：根据国企、大厂与岗位方向突出能力、业务影响和关键词连接。

项目采用 clean-room 方式实现：研究了 Resume.com 的公开信息架构与常见简历产品流程，但未复制其商标、受版权保护的文案、图片、模板、源码或不可见的后端架构。

## 当前可用能力

- 凝练的 AI 简历首页，以及合并“新建”和“工作台”的单一入口
- 186 个目标适配方案：101 所院校、85 家企业，按地区或企业类型二级选择
- 16 套原创专业版式（留学与求职各 8 套），覆盖学术研究、国际申请、金融咨询、科技产品、工程制造、央国企等 8 类真实阅读情境；创建时展示缩略图、推荐理由与非官方声明
- 目标搜索、自定义目标、场景标签与非官方编辑建议说明
- 服务端简历 CRUD、软删除与用户级资源隔离
- 完整账号体系：邮箱注册/验证/登录、Google、GitHub、微信网站应用扫码、中国大陆手机号验证码、邮箱/手机号找回密码与双重密码确认
- 访客草稿登录后自动迁移；账号中心支持资料、邮箱、手机号、第三方账号绑定、密码、会话级 TOTP / 恢复码、设备会话、完整数据包导出和永久删除管理
- 最新用户协议与隐私版本由服务端强制确认；管理员必须完成当前会话 MFA，敏感操作还要求近期登录
- D1/SQLite 持久化、修订快照和审计事件
- 六大简历章节编辑、实时 A4 预览、自动保存
- 求职场景支持独立保存目标岗位、单个 JD、来源标签/链接与记录日期，并生成“岗位要求 → 用户原文证据 → 缺口 → 撰写动作”的确定性证据地图
- 用户可从证据地图选择一条岗位要求和一条可定位原文，获得结构化改写草稿、修改理由、引用证据与待补事实；确认后精确替换原文并可撤销，不再向经历中追加无来源草稿
- 服务端 DeepSeek Responses API 适配层、结构化输出校验、逐次同意记录、最小化模型输入，以及会话 / 网络 / 全局配额、单会话单请求和四路全局并发闸门；模型返回的原文定位与草稿还需通过本地事实安全门，未配置模型或调用失败时透明降级为基础分析
- 透明商业层：基础编辑、模板、目标分析与全部导出永久免费；访客态可体验 1 次且不结转，注册账户固定另获 5 次，成功的 DeepSeek 优化按次结算，失败自动返还；20 / 80 / 200 次额度包提供阶梯优惠且不自动续费
- 可审计的额度批次、预占/结算/释放流水、订单结构与模型 token 成本记录；商业余额、滥用限流和全站人民币日预算相互独立
- 可重放建议的显式生命周期、积分/成本/结果原子结算、租约围栏、只读对账及受保护的分批修复任务
- 编辑器内统一完成打印 / 存为 PDF、ATS 纯文本和网页简历输出
- 单文件网页简历默认隐藏联系方式，并使用严格 CSP/HTML 转义
- 根据当前目标与证据缺口，在填写区下方最多展示一条可选学习提示；来源包括中国大学 MOOC、Khan Academy、Coursera、edX、Microsoft Learn 等官方页面
- 我的简历：新建、搜索、筛选、重命名、复制与删除草稿
- 服务端 RBAC 管理台：平台指标、用户查询、角色调整、账号停用/恢复、内容治理和健康检查
- 响应式布局、键盘焦点、减少动态效果与打印样式

## 本地运行

环境要求：Node.js 22.13 或更高版本。

```bash
npm install
npm run dev
```

开发服务器会输出实际本地地址。`npm run dev` 的 `predev` 会先把 `drizzle/` 中尚未执行的迁移应用到本地 Miniflare D1；也可以单独运行 `npm run db:migrate:local`。早期版本已经由请求期初始化完成的本地数据库会被无损写入迁移台账，再继续执行后续迁移。

生产数据库结构只由部署阶段随站点发布的 Drizzle 迁移创建或升级。请求期的 `ensureDatabase` 不执行 `CREATE` / `ALTER`，只用一次只读查询确认结构就绪，再检查目录版本并按需写入模板与目标目录种子；缺少迁移时会直接报告数据库未就绪，不会在用户请求中尝试修表。旧版线上 D1 如果已有业务表但缺少迁移台账，必须按 [Legacy D1 无损升级手册](docs/legacy-d1-upgrade.md) 使用严格指纹 bridge 收养，禁止直接猜测或补写后续迁移。

### 认证配置

生产环境必须显式设置 `APP_ENV=production`、`BETTER_AUTH_SECRET`（高强度随机值）、`BETTER_AUTH_URL` 与同源的 `NEXT_PUBLIC_SITE_URL`（站点完整 HTTPS origin）、独立的 `PROMO_REDEMPTION_PEPPER`、`MAINTENANCE_SECRET` 和 `AUTH_ADMIN_EMAILS`（逗号分隔）。各登录渠道按需配置：

| 能力 | 环境变量 |
| --- | --- |
| 邮件验证 / 找回密码 | `RESEND_API_KEY`、`AUTH_EMAIL_FROM` |
| Google | `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET` |
| GitHub | `GITHUB_CLIENT_ID`、`GITHUB_CLIENT_SECRET` |
| 微信网站应用扫码 | `WECHAT_CLIENT_ID`、`WECHAT_CLIENT_SECRET` |
| 中国大陆手机号短信 | `TENCENTCLOUD_SECRET_ID`、`TENCENTCLOUD_SECRET_KEY`、`TENCENT_SMS_SDK_APP_ID`、`TENCENT_SMS_SIGN_NAME`、`TENCENT_SMS_TEMPLATE_ID`，可选 `TENCENT_SMS_REGION` |

Google、GitHub 和微信开放平台的回调地址统一为 `https://你的域名/api/auth/callback/{provider}`，其中 `{provider}` 分别是 `google`、`github`、`wechat`。本地开发未配置邮件/短信服务时，验证链接和验证码只输出到本地服务终端；生产环境不会使用该回退。

## 质量检查

```bash
npm run verify:release
```

数据库结构定义保存在 `db/schema.ts`，所有已生成并审查的迁移保存在 `drizzle/`。新结构必须先增加迁移并在本地执行 `npm run db:migrate:local`，不能把 DDL 放回 API 请求路径。

## 数据与安全说明

- 未登录时使用浏览器级私有访客空间；正式账号使用 Better Auth 的 HttpOnly 会话。登录后自动认领访客草稿，所有简历 API 都在服务端校验资源所有权。
- 邮箱、Google、GitHub、微信与手机号按环境变量独立启用；缺少外部凭据时界面明确标记“待配置”，不会伪装成功。管理员与所有已启用 TOTP 的普通账号都必须在当前会话完成二次验证。
- 默认基础分析不会调用第三方模型，也不会自动虚构成绩、工作经历或量化成果；CV 正文会发送到本平台 API 进行检查与保存。
- 只有服务端显式设置 `DEEPSEEK_ENABLED=true`，同时配置 API key、允许的 HTTPS base URL、受支持模型和有效日预算，且用户在编辑器中主动勾选后，当前请求才会发送给 DeepSeek Responses API；系统会记录同意版本、用途、目标简历与时间，不记录同意时的 CV 正文。
- 生产环境必须额外配置独立的 `PROMO_REDEMPTION_PEPPER`（至少 32 位高熵值），用于对已验证登录身份做 HMAC、防止删号重复领取启动额度；不得与认证 secret 共用。
- 必须配置独立的 `MAINTENANCE_SECRET`。外部调度器至少每天调用一次 retention（每次直接执行有界批次并循环至 due 指标归零），再检查 reconciliation dry-run 并按需以 `?apply=true` 恢复；对非 2xx 或持续积压告警。批量维护不进入用户请求热路径。
- DeepSeek Responses API 按无状态请求使用；概览分析通过显式字段投影排除姓名、邮箱、电话、教育/经历所在地和项目链接，所有自由文本先做常见招聘联系方式脱敏，JD 只发送优先提取的最多 12 项要求。可直接应用的草稿必须引用当前简历中的稳定原文位置，并严格等于经过审计的确定性安全压缩结果；其他自由改写不会直接写入简历。服务商的数据处理仍以其协议与账号配置为准。
- 岗位分析只以用户粘贴并确认的单个 JD 文字为准；BOSS、智联等第三方链接仅作为可选出处记录，系统不自动打开、调用平台 API 或批量抓取。当前版本不上传岗位截图，用户可先用设备文字识别后粘贴；JD 不进入公共岗位库或训练语料。
- 真实用户上线前仍需完成个人信息保护法/GDPR 专项评估、服务提供方协议审查和撤回同意流程。
- 产品管理员不能获得服务器 Shell 或宿主电脑控制权；产品角色与云端运维 IAM 必须隔离。
